2. Freeze, gate and rebuild

  1. Freeze and gate. Freeze the final head and run the full gates on it: pytest, tox, poetry check --lock and python scripts/generate_merge_configs.py --check. Passing the frozen-head gate closes the three gate-only holds (#1324, #1343, #1346).

  2. Stage the rebuild worktree.

    • On the M1 host: The staged worktree (data/validation-upstream-20260930.DbltzT/worktree) is host-local to that machine and holds its receipt-bound data/raw. Move that worktree to the frozen head without disturbing its staged inputs, stage any newly pinned inputs with targeted downloads recorded in its staging receipt, and run python -m kg_microbe.utils.release_preflight data/raw.

    • On any other host (where data/validation-upstream-20260930.DbltzT/worktree is not present on disk): Create a dedicated rebuild worktree at the frozen head, stage a receipt-bound data/raw from pinned release assets / verified local caches (never a blanket kg download -i), and verify all pins upfront with poetry run python -m kg_microbe.utils.release_preflight data/raw.

    • Note: Manual #1413 go.db.tmp / go-relation-graph.tsv cleanup is now performed automatically before every SemSQL build (#1663; see section 5).

  3. Rebuild the 15 standard-merge producers.

    • Where to run. Run inside the staged worktree with its default data/raw and data/transformed, without -i or -o, using one process per source (kg transform -s <source> or the phased runner) so memory does not accumulate across sources (#1046).

    • Which sources. Name each producer explicitly. The default kg transform batch has 18 sources, including bakta, cog and kegg, which are outside the standard merge.

    • No reuse. Rebuild in these dependency phases, and never reuse or relabel earlier outputs as fresh:

    Phase

    Producers

    1

    ontologies: the whole 14-member producer (the only phase that builds go.db, #1643), with actual finalization, freshness and authority-epoch checks before anything else

    2

    ontologies_stubs, gtdb, bacdive, madin_etal, metatraits, rhea_mappings, prego (habitat)

    3

    gold, lpsn, mediadive, bactotraits, metatraits_gtdb

    4

    lpsn_api, microbedecoder

    poetry run python scripts/transform_phases.py derives these phases from each source’s TRANSFORM_INPUTS, and hpc/submit_phased_transforms.sh submits them on Slurm, one array job per phase, each starting only after the previous phase succeeded (#1567).

    rhea_mappings runs inside this rebuild, not as a separate Rhea run.

    • Inputs. It uses the pinned Rhea pair (mappings/rhea_release.json) and the prepared chebi.db, go.db and ec.db label databases, which depend on the ontology preparation.

    • Release label. Rhea label 142 is a local cache label, not verified tagged-release provenance.

    • No fallback. It never falls back to the latest release or a cache.

  4. Merge. Create a fresh merge, with no semantic edits after serialization. The canonical merge still excludes MONDO. Then reconcile:

    • source observations;

    • category unions;

    • archive and member identities;

    • manifests;

    • zero unexpected | pooling anomalies in single-valued node columns (#1398, #1674).

  5. Review the exact archive at 100% row coverage (#810). Run fresh model, external KGXVal, strict-KGX and path reviews on that exact candidate with full row coverage (--merged --max-rows 0, or --max-rows at least the merged edge total). Partial-sample kg-model-review artifacts print a bold **sampled M of N rows (P%)** warning and are rejected by kg_release.py (needs-attention). Strict-Biolink exceptions stay visible. Project conventions stay distinct from strict conformance, and both stay distinct from scientific acceptance.

  6. Close. On acceptance, close the held issues in section 4.

These steps follow the acceptance steps in Remaining 93 diagnostics, which also records per-package status, and in Rhea directions. The native RO row in the per-package table predates #1400; RO relations gives the current 516-assertion scope.
