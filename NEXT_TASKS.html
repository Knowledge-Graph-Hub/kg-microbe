1. Before freezing the rebuild candidate

Each item here can change producer output or shared code. Resolve it, or defer it explicitly, before the head used for the rebuild is frozen. Anything that changes output after the freeze means rebuilding again.

Blockers

  • #1420: exact-byte pins cannot be reproduced. Several reviewed policies pin the whole-file SHA-256 of raw inputs, and a fresh environment cannot obtain those exact bytes:

    • some pins are of files the transform used to rewrite in place, with no pristine copy kept: ro.json, pato.json, uberon.json, mondo.json, foodon.json;

    • some files are built locally: go.db, ncit.db, and ROBOT-converted JSON such as upa.json;

    • lpsn_gss.csv is account-gated, so kg download cannot fetch it;

    • the rest come from rolling URLs, which serve whatever is current:

      • envo.json, pato.owl and mesh2026.nt.gz;

      • Rhea’s rhea-directions.tsv and rhea.rdf.gz;

      • MicrobeDecoder’s database.zip. Its upstream changed on 2026-09-08, so a fresh download fails today.

    Even kg download -i cannot reproduce them.

    • Where it fails. Outside the staged worktree, each affected producer fails closed at its first mismatched input.

    • Skipped sources. In a multi-source batch, every source that declares the ontologies transform in TRANSFORM_INPUTS, directly or transitively, is then skipped.

    • When it fails. Most pins are checked only when their ontology is parsed, so the main checkout aborts at ENVO after hours of NCBITaxon and ChEBI work.

    The decided fix re-binds the policies one at a time, each with its own independent review; the plan lists the steps. #1441 belongs to the same work: PO’s imports are still fetched live, so ontologies_stubs needs the network during the rebuild.

  • #1421: BacDive withheld supplied-taxid records drop out of deposit resolution. As a result, the deposits Chol-1, SN-1 and ATCC-15578 would equate unrelated organisms through close_match. The fix is in review as PR #1467.

2. Freeze, gate and rebuild

  1. Freeze and gate. Freeze the final head and run the full gates on it: pytest, tox, poetry check --lock and python scripts/generate_merge_configs.py --check.

  2. Move the staged worktree. The staged worktree (data/validation-upstream-20260930.DbltzT/worktree, detached at 845f2add1) holds the receipt-bound data/raw for the rebuild.

    • Clean up the #1413 leftovers first (section 5).

    • Move the worktree to the frozen head without disturbing its staged inputs.

    • Stage the inputs the frozen head newly pins, and record them in the staging receipt. These include at least MicrO’s 20 micro_imports/ modules, micro.owl at its pinned commit if its bytes differ, and anything the #1420 work re-pins.

    • Do not run a blanket kg download -i.

  3. Rebuild the 15 standard-merge producers.

    • Where to run. Run inside the staged worktree with its default data/raw and data/transformed, without -i or -o. Some producers resolve paths relative to the code checkout (RAW_DATA_DIR in transform_utils/constants.py).

    • Which sources. Name each producer explicitly. The default kg transform batch has 18 sources, including bakta, cog and kegg, which are outside the standard merge.

    • No reuse. Rebuild in these dependency phases, and never reuse or relabel earlier outputs as fresh:

    Phase

    Producers

    1

    ontologies: the whole 14-member producer, with actual finalization, freshness and authority-epoch checks before anything else

    2

    ontologies_stubs, gtdb, bacdive, madin_etal, metatraits, rhea_mappings, prego (habitat)

    3

    gold, lpsn, mediadive, bactotraits, metatraits_gtdb

    4

    lpsn_api, microbedecoder

    rhea_mappings runs inside this rebuild, not as a separate Rhea run.

    • Inputs. It uses the pinned Rhea pair (mappings/rhea_release.json) and the prepared chebi.db, go.db and ec.db label databases, which depend on the ontology preparation.

    • Release label. Rhea label 142 is a local cache label, not verified tagged-release provenance.

    • No fallback. It never falls back to the latest release or a cache.

    The previous attempt stopped in phase 1, at ENVO’s native RO evidence (#1400). #1401 added the fix.

  4. Merge. Create a fresh merge, with no semantic edits after serialization. The canonical merge still excludes MONDO. Then reconcile:

    • source observations;

    • category unions;

    • archive and member identities;

    • manifests.

  5. Review the exact archive. Run fresh model, external KGXVal, strict-KGX and path reviews on that exact candidate. Strict-Biolink exceptions stay visible. Project conventions stay distinct from strict conformance, and both stay distinct from scientific acceptance.

  6. Close. On acceptance, close the held issues in section 4.

These steps follow the acceptance steps in Remaining 93 diagnostics, which also records per-package status, and in Rhea directions. The native RO row in the per-package table predates #1400; RO relations gives the current 516-assertion scope.

5. Local checkout housekeeping

From #633 (2026-08-01) until #1401 fixed #1413, a unit test could run a real semsql make inside data/raw whenever data/raw/go.owl was present. In any checkout where that happened:

  • An interrupted build leaves data/raw/go.db.tmp and data/raw/go-relation-graph.tsv. Delete both before the next real GO build, because a stale go-relation-graph.tsv can short-circuit semsql make.

  • A completed build may have replaced data/raw/go.db itself and left no stray files. Check go.db against its pinned digest, a3903d4c…, in mappings/go_imported_subject_restrictions.json and mappings/upa_reaction_projection_dispositions.json.

The staged worktree (data/validation-upstream-20260930.DbltzT/worktree) has both stray files. Its data/raw is receipt-bound, so remove only those two files, and record any later additions in the staging receipt.
