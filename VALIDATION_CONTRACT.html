KG-Microbe validation contract v1

Machine identifier: kgm-validation-contract-v1, exposed by kg_microbe.utils.kgm_validation_profile.validation_contract(). This contract distinguishes evidence layers; it does not replace their implementations or introduce a graph repair, strict-validator suppression, or automatic release gate. The original validators and their findings remain authoritative for their own scopes.

Record each validator’s scope, input/model/code hashes, completion status and limitations. Process exit 0, a present report, unchanged counts or a successful archive write is not a scientific pass. Source/merge validation is mandatory; optional diagnostics retain their separate behavior. A model-review allowance is never silently transferred to strict KGX. No layer in this module grants release approval. See SOURCE_MERGE_CONTRACTS.md, PREMERGE_SOURCE_FINALIZATION.md, SEMANTIC_MODEL_DECISIONS_20260914.md and the model/path review skills for the actual rules and their evidence requirements.

Canonical transport is not the strict validator’s object schema

KGM’s mandatory edge TSV columns are subject, predicate, object, relation, primary_knowledge_source, knowledge_level, and agent_type. Edge id and KGX’s internal key are deliberately absent. The installed strict KGX validator requires an edge identifier and currently emits that missing-ID callback twice per edge. Retain those errors; do not fabricate identifiers or reinsert serializer internals to disguise them.

Canonical TSV cells are strings. Pipe-delimited category/provenance/xref tokens in this transport are not Python lists in a validator’s in-memory object schema. Report conversion rules explicitly and separate genuine scalar-field violations from transport/type callbacks. Native METPO/MICRO and local source namespaces also need the appropriate prefix context; a missing registry prefix is neither evidence of an invalid biological identity nor permission to silently alias its spelling.

The reviewed candidate’s original 76,611,293 strict callbacks remain recorded as errors, not unique invalid rows. The 17,637,435 repeated unit logger warnings are a different stream, not additional callback findings. The source/category disposition report does not suppress either stream, change the pinned schema/context, or claim a strict pass. Strict delta reconciliation must retain original totals and full source attribution limits.

The legacy-named merge report

merged-kg_reference_resolution.tsv now contains a validation summary, not a list of semantic edits. Its columns are check, status, nodes, edges, and audited_native_nameless_nodes; its successful check is canonical_representation_and_endpoint_closure_no_semantic_rewrites. write_merge_validation_report() validates the original pair before writing that receipt. Failures abort rather than repair graph bytes. Semantic audit files belong beside each source output: source_canonicalization.tsv, source_reference_resolution.tsv and go_reference_resolution.tsv (possibly ontology-prefixed), bound by source finalization.

The additional nameless-node count distinguishes a verified original native declaration from an anonymous endpoint invented during graph loading. Under #1316 a native GOLD referent can genuinely have no name. Such a row must match an exact declaration already verified during source admission, including its native taxon/audit evidence and admitted metadata. Neither an identifier alone nor a GOLD prefix grants an exception. Missing or changed proof aborts; merge does not invent a name, infer a category, resolve a new identity, or modify the row. The count is zero when no such declaration is used. The full GOLD producer and late-admission integration still require their separate candidate tests.

Together with the 70 registered native-predicate extensions, this gives 83 explicitly supported project-scope dispositions and 93 action-required diagnostics. It does not mean the graph passes strict or scientific validation. The 59 generic endpoint cohorts now have exact source/relation ownership and witnesses; complete authoritative semantic ancestry is still missing, so they are not accepted or silently deleted. The finite catalog states the concrete action for each signature and retains the original strict finding.

The CSV omits subject/object identifiers, the opposite category set, original relation and provenance. Several graph signatures can therefore serialize to the same diagnostic row. None of the CSV repetition counts can be interpreted as graph-edge counts, and identical signatures cannot establish preservation.

To finish an individual category acceptance, retain exact source assertions and both endpoint declarations, test the precise documented rule (including relation and namespace conditions), bind selected authorities, and record incompatible/unattributed cases as upstream work. Do not infer an exact class, taxon, compound or assay meaning from a label or category alone. The finite classifier deliberately has no function that turns a category signature into a house-rule pass. Reference evidence is attached only when the complete original CSV hash, all occurrence counts and an explicitly supplied graph archive hash match the pinned reference epoch. Byte-identical CSVs alone do not identify their graph. With no supplied archive, classification still runs, but reference_evidence_applies is false and no historical row assessments are attached. The output always identifies the historical reference_epoch separately.

Run without changing original evidence

poetry run python scripts/classify_kgxval_report.py \
  --report data/<actual-review>/model/model-kgxval-errors.csv \
  --report-sha256 20ef42bf0eaf4683066f9bdcc9e2e26d7cdee1f98b4f0b4db7a2fe98877a8a6c \
  --require-reference-cohort \
  --graph-archive data/<actual-candidate>/merged-kg.tar.gz \
  --output data/<new-evidence-directory>/kgxval-dispositions.json

Use the exact local report selected by the caller, not an implicit latest archive. The output parent must already exist and the output file must be new. No ontology service or graph TSV is read. The original CSV remains byte-identical; the output binds its input, profile, optional archive and implementation/registry identities before and after classification. Archive bytes are streamed for hashing, not extracted or revalidated. Supplying the matching archive and CSV does not prove that a validator produced that CSV from that archive; original run receipts remain necessary. The model hashes identify the reference epoch, not proof that an arbitrary CSV was generated by that model. With --require-reference-cohort, a supplied archive differing from the reference aborts; otherwise it is classified without attaching historical assessments.

The finite catalog requires a join locator, digest and byte size, paired endpoint declarations matching witness identifiers/categories, and each original full-row digest. These are local integrity/shape guards, not authentication of the external saved join. Portable witness assertions omit original columns, so their full-row digests cannot be recomputed from that reduced projection. Independent review checked all retained counters, witnesses, endpoint declarations and full-row digests against the original saved join, without rescanning the graph.

Exit codes: 0 means only registered native-extension diagnostics were classified (still not a strict/scientific pass); 2 means classified findings require additional review; 3 means an unregistered exact diagnostic was encountered. Invalid headers/profiles/input digests abort. The complete reference run intentionally exits 2. Omitting --require-reference-cohort allows a supplied subset or a later report to be classified, but does not certify completeness of its originating validator run. Empty reports do not certify completion. Unknown diagnostics remain visible and cannot inherit a prefix or category waiver; a newly reviewed cohort requires explicit curation and a profile revision.

The classifier never changes strict_conformance, scientific_acceptance or release_authorized to true. Do not use classification_complete as an acceptance verdict.

Regression coverage

tests/test_kgm_validation_profile.py uses committed tiny immutable diagnostic and graph fixtures. It tests every finite entry, all six signature fields, new native IDs, report multiplicity, corruption/partial-cohort controls, conservative exit statuses, and actual merge-validation success/failure with byte-preserved graph files. The existing canonical serializer, source-finalization, admission and semantic-model tests remain separate; passing the new classification tests does not replace them.

BacDive recipe-class correction from this review

The 16 assertions matching the GrowthMedium subclass diagnostic are not the whole emitter scope. A complete read-only source inventory found 1,575 distinct recipe-class assertions emitted by BacDive with subclass_of, original relation rdf:type, and supplier infores:metpo. They were generated by BacDive code, not native METPO axioms. METPO defines the parent METPO:1004005 (growth medium); catalogue recipes are named recipe classes, consistent with the existing MediaDive hierarchy, not individual culture batches.

The upstream emitter now uses rdfs:subClassOf and infores:bacdive. Subject, predicate, object, knowledge level and agent type remain unchanged. This does not change the parent ontology declaration’s own provenance. Positive and negative growth assertions retain their exact native predicates and evidence; ambiguous values still produce no observation. The prospective full-row difference and unchanged-input guards are retained in data/validation-upstream-20260930.DbltzT/bacdive-recipe-source-inventory-01.json. The original source and candidate remain untouched. An actual BacDive rebuild, complete assertion conservation check and fresh model/path review are still required; this code change is not a post-merge repair or a new KGXVal waiver.

Other producer corrections from this review

The shared MetaTraits worker now declares a taxon when its first quantitative phenotype assertion is emitted, even without a mapped categorical trait. Exact fixtures cover all 25 affected GTDB records and all six quantitative emission routes; empty or deferred records do not acquire edgeless taxon declarations. The phenotype observations are unchanged. The existing GTDB hierarchy pass will also see these newly declared taxa: 17 have current accession-based species bridges, so the rebuild can add existing-policy hierarchy and NCBI crosswalk edges. This is not a promise of exactly 25 changed graph rows or permission for new identity assertions.

MediaDive’s explicit retained solution identifiers now receive the solution category (ChemicalMixture) before generic ingredient category lookup. The current source inventory identifies solutions 6257, 6420 and 6572 as affected. Only 6257 has a downloaded child formulation; the latter two have explicit solution_id references but missing child recipes. Correcting their source role does not invent composition, identity or subclass assertions.

These fixes remain upstream implementations awaiting production rebuild and conservation checks. The finite reference catalog describes the original pinned epoch, not a retrospective acceptance of repaired output. Ontology metadata exclusion also occurs only upstream: exact annotation-property evidence is required, true semantic punning is preserved, and mandatory exclusion audits and consumed authority hashes accompany finalization.
