# METPO 2026-06-02 release vs. kg-microbe proposal TSVs

Comparison of the proposed terms in
`mappings/metpo_proposal_classes_robot.tsv` (37 classes) and
`mappings/metpo_proposal_properties_robot.tsv` (7 properties) against the
upstream METPO release tagged `2026-06-02` in
[berkeleybop/metpo](https://github.com/berkeleybop/metpo/releases/tag/2026-06-02)
(metpo.obo, 1455 terms + 132 typedefs).

Numeric IDs are stable; the release prefix is lowercase `metpo:` while our
proposals use `METPO:` — these are treated as the same CURIE. Numeric ID
ranges seen: classes `1007005-1007093`, object/datatype properties
`2000064-2000719`.

Companion data files in this directory:

- `metpo_2026_06_02_missing.tsv` — proposed IDs absent from the release
- `metpo_2026_06_02_present.tsv` — proposed IDs present, with diff column

Source script (kept under `/tmp` while iterating; rerun whenever a new
METPO release ships): the diff is generated by
`/tmp/metpo-release/diff_proposals.py` taking the two proposal TSVs and a
released `metpo.obo`.

## TL;DR

| Bucket | Count |
|---|---|
| Missing from release | **9** (6 HIGH classes + 2 CRITICAL props + 1 HIGH prop) |
| Present, content differs from proposal | 28 |
| Present, identical to proposal | 7 |

All 9 missing items belong to the **environmental-tolerance min/max + growth
optimum** family — every proposal in that group failed to land, while every
proposal outside that family landed. This is the most actionable finding:
either the upstream PR didn't include those rows or they were intentionally
deferred, and our metatraits pipeline is the one that needs them.

## 2. Present with diffs (28) — patterns

The 28 diffs cluster into four mechanical patterns; no semantic
disagreements were observed.

### Pattern A — DEF-FORM stylistic rewrite (most diffs)

Upstream PR
[berkeleybop/metpo#460](https://github.com/berkeleybop/metpo/pull/460)
added a DEF-FORM guardrail that rewrites every textual definition to the
genus-differentia form `"A <parent_label> [characterized by|in which|that] …"`.
Our proposal definitions were written in the older `"A phenotypic quality
describing …"` form and were all rewritten on ingest.

Examples:

- `METPO:1007070 pressure tolerance`:
  - proposed: `A phenotypic quality describing the ability to grow under elevated hydrostatic pressure.`
  - release: `A phenotype characterized by the ability to grow under elevated hydrostatic pressure.`
- `METPO:1007064 circular colony`:
  - proposed: `Colony with a regular round outline.`
  - release: `A colony shape that has a regular round outline.`

**No action needed** — release wording is the canonical form going forward;
update our proposal TSV to match the released text so future diffs stay
clean.

### Pattern B — Parent reassignment to METPO:1000059 (12 classes)

Every class we proposed under `parent = METPO:1000000` (root) was
re-parented to **`METPO:1000059`** (`phenotype`) in the release. Affected
IDs: `1007005, 1007062, 1007070, 1007072, 1007073, 1007074, 1007076,
1007077, 1007080, 1007081, 1007082, 1007089` (and their descendants
implicitly).

**Action:** update our proposal TSV to use `METPO:1000059` as the parent
for everything currently at `METPO:1000000`; this is the curator
convention.

### Pattern C — Cross-reference (xref) drop

7 cases where we provided a GO or PATO xref that did not survive into the
release:

| Term | Dropped xref |
|---|---|
| `METPO:1007005 flagellar arrangement` | `GO:0001539` |
| `METPO:1007062 colony morphology` | `PATO:0000052` |
| `METPO:1007063 colony shape` | `PATO:0000052` |
| `METPO:1007076 capsule presence` | `GO:0042597` |
| `METPO:1007077 biofilm formation capability` | `GO:0042710` |
| `METPO:1007083 catalase positive` | `GO:0004096` |
| `METPO:1007085 oxidase positive` | `GO:0004129` |
| `METPO:1007087 urease positive` | `GO:0009039` |

The release does keep `IAO:0000119` (definition source) xrefs sourced from
OMP / wikidata. The dropped values are all `oboInOwl:hasDbXref` entries —
candidates for re-proposal as `skos:relatedMatch` or
`skos:closeMatch` if the curators want to avoid `hasDbXref` for
non-equivalent terms.

**Action:** confirm with METPO curators whether these xrefs were dropped
intentionally. If so, re-encode in our local proposal TSV using the
preferred predicate; if not, re-propose.

### Pattern D — Object-property range narrowed (2 props)

Both isolation-quality properties had their range tightened:

| Property | Proposed range | Released range |
|---|---|---|
| `METPO:2000067 isolated from host with quality` | `PATO:0000001` | `METPO:1000188` |
| `METPO:2000068 isolated from environment with quality` | `PATO:0000001` | `METPO:1000188` |

`METPO:1000188` is the upstream "quality" surrogate (the metpo-internal
class for quality-typed values). Functionally equivalent for the
metatraits transform — our transform writes objects whose category aligns
with this class — but our proposal TSV should be updated so future diffs
stay clean.

`METPO:2000068` also has a one-word definition tweak (em-dash → semicolon)
which is the same DEF-FORM pattern (A).
