Reviewed release inputs

Several transforms apply reviewed policies under mappings/ that bind the upstream data they were checked against. Until #1420 some of those bindings were whole-file digests of files no download could reproduce: JSON converted by ROBOT, a mondo.json an older transform rewrote in place, a locally built go.db, a gunzipped ncit.db, and inputs fetched from rolling URLs. A fresh checkout therefore failed, often hours into a run. This runbook says how each input is now fetched and bound, and how to stage a raw directory for a rebuild.

Moving any of these to a newer upstream release means re-reviewing every policy that binds it, then updating the URL, the policies and their tests together.

The preflight

Before any source runs, kg transform asks each selected source for missing prerequisites. When ontologies is selected, that includes kg_microbe/utils/release_preflight.py, which checks:

  • every file in the first row of the table, and the Biolink model the NCIT and MeSH policies pin: each must exist and match the digest every policy that pins it agrees on;

  • ncit.db, which must be inside the raw directory. The NCIT policy reads it when FOODON and MediaDive finalize, and ontologies_stubs reads it too. MediaDive and ontologies_stubs run this part of the check themselves. A run unpacks ncit.db.gz only when ncit.db is missing and never replaces an existing copy, so an existing ncit.db must have a SQLite header and, with the archive beside it, the archive’s unpacked size. Otherwise a newer download would be read silently in its place. Size cannot tell apart two releases of the same size; the run’s receipt records the release it read. Without ncit.db, the archive is read to its end and must unpack to a SQLite database, so a truncated, empty or wrong download fails here, not hours in;

  • that an existing upa.json is the pinned conversion. A missing one is fine: the run derives it from upa.owl.

A single ontology (-s go, -s uberon, …) is checked for the pinned files its own run reads, listed in SINGLE_ONTOLOGY_INPUTS; -s ec or -s chebi reads none of them. Some runs also read JSON another ontology’s run converts: the native RO suppliers (pato, uberon, envo, mondo) read ro.json, and pato, mondo and foodon read uberon.json for their reviewed UBERON temporal classes. Run ro and uberon first; the check does not cover these files.

Nothing runs until they all pass, so a stale download fails in seconds rather than after NCBITaxon and ChEBI. A message names the file, its digest, the policies that pin it and the command that fetches it. To check without starting a run, use python -m kg_microbe.utils.release_preflight data/raw, which exits 1 when there are problems.

Other sources do not run this check, apart from the ncit.db part that MediaDive and ontologies_stubs run. Rhea and MicrobeDecoder check their own pins when they run, and sources such as MediaDive and Madin meet the category pins when they finalize.

A file that does not match is usually one of these:

  • A rolling download from before #1420. When the download manifest (data/raw/.download_manifest.json) recorded the old URL, kg download -t ontologies re-fetches the file from its release URL. A file with no record is left alone, so move it aside first.

  • A file rewritten in place. Older transforms rewrote mondo.json after dropping deprecated terms. Its recorded URL can be the current one, so kg download will not replace it. Move the file aside, then run kg download -t ontologies.

  • A hand-copied or hand-edited file. Treat it like a rewritten one.

  • An ncit.db unpacked from an older archive. kg download -i -t stubs replaces ncit.db.gz but leaves ncit.db. Delete ncit.db, and the next run unpacks the new archive.

Never edit a policy’s digest to match a file on disk: the digest records what was reviewed.

External prerequisites

  • ROBOT and Java. kg download -t tools installs the pinned ROBOT; Java must be on PATH. The ontologies_stubs preflight checks both.

  • rdftab and relation-graph. SemSQL builds (go.db, chebi.db and others) run both from PATH, and no preflight checks them. Install rdftab v0.1.1, the version SemSQL itself uses, from the rdftab.rs release. On Apple silicon the x86_64-apple-darwin binary runs under Rosetta. The repository has no lock file for building it from source, so a source build may not reproduce the same databases.

Staging a raw directory for a rebuild

  1. Run kg download for the tags you need, and stage the manual inputs: Rhea with stage_snapshot --source-archive (see the Rhea runbook), and lpsn_gss.csv by hand (see Data hosting).

  2. Run python -m kg_microbe.utils.release_preflight data/raw and fix each message as above until there are none. kg transform runs the same check first, but once it passes the run starts.

  3. If ncit.db.gz or mesh2026.nt.gz has moved upstream, the stub sources still accept it as long as the reviewed statements are unchanged. If one changed, the source fails closed: re-review that policy before changing it.
