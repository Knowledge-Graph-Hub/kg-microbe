# Real native MIM synthetic fixture constructor

The adjacent `../stable_mim_native_fixture.py` is test-only orchestration. It dynamically loads the exact caller-pinned `tests/test_source_bindings.py::Fixture` from MediaIngredientMech, then uses the selected native source, ordinary external and companion producers. It never replays a saved success boolean or edits original fixtures/code/campaign data. Each invocation requires an absent private output root and Python 3.13 executable bytes, exact code HEAD, and exact upstream fixture SHA256. Producer/helper/schema/lock bytes are checked against that revision and rechecked after execution. The new fixture repository has an explicitly synthetic Git revision; this is never presented as the selected upstream code revision.

The companion construction is adapted from `native_products` in the existing `native-product-counting-helper-v2/test_count_products.py` recipe (its complete native export calls and independent scope evidence), which in turn uses MediaIngredientMech source fixtures. The original recipe is an uncommitted private campaign artifact; its path/hash is recorded in the accompanying handoff, not represented as an upstream release. The native source fixture is selected by explicit revision and hash at runtime, not vendored or silently replaced. No package installation, provider, graph build, native campaign preparation/adoption or network operation is performed.

Variants:

* `baseline`: the actual native fixture's four source cases/five owners/four external rows and one independently reviewed scoped companion mapping.
* `narrow`: adds a fifth explicitly assessed source owner sharing CHEBI:1, that owner's own exact row, and a separately judged narrow row for owner 2 (Hydrate), which already has its explicit exact registry sibling. All original four rows remain; no external identity implies source support.
* `legacy-held`: extends `narrow` with the exact legacy alias `MIM:L-alpha-Phosphatidylcholine` on owner 1 only, retaining its numeric ID. Current owner hashes, separate external evidence, companion review and fresh native source pairs are regenerated by their actual constructors. This is a synthetic unresolved-lineage consumer case, not evidence that this fixture owner is the real P3556 material. Owner 1 and owner 5 share the independently supported CHEBI:1 target; a consumer hold must follow only the explicit legacy owner join, never the common target or another owner. No actual historical hold is released.
* `held`: source 1 retains a literal scientific hold; source 4 is ownerless. Fresh separate native primary/skeptical reports withhold both, while independent external/companion decisions remain unchanged.
* `rename`: moves/renames owner 4, preserves its numeric ID and original aliases, adds a legacy alias and obtains fresh native source reports.
* `empty`: zero external rows with genuine native source and external products, using explicit `companion_mode: absent/v1`. No companion review, output or claims file is constructed. All companion result references and pins are null. The earlier failed annotation-only companion construction is preserved in private execution evidence; its native scoped-mapping prerequisite is not waived.
* `all-withheld`: retains the complete original four external rows with separately authored negative external evidence and all four native external decisions WITHHOLD. Fresh native source reviews still support the four source identities independently. This also uses explicit `absent/v1` with no companion artifacts, rather than constructing or validating a fake empty companion.
* `terminal-invalid`: appends a valid synthetic terminal lifecycle event while the old owner remains current. Actual native inspection must reject the retired current ID. The result captures that narrow expected refusal; no successful product is claimed.

Required-companion variants (`baseline`, `narrow`, `legacy-held`, `held`, `rename`) explicitly return `required/v1` and retain actual native companion generation and validation. There is no exception handler that converts an invalid supplied companion into absence. The absent-companion mode is an explicit versioned consumer choice; no native MIM capability, producer, validator or scientific gate changes.

The constructor prints result JSON on stdout and leaves native diagnostics on stderr. `FIXTURE-RESULT.json` retains actual output manifests/pins and source/runtime provenance. These are explicitly synthetic test judgments, not current campaign scientific acceptance or KG production permission. The parent integration tests own execution and assertions.
